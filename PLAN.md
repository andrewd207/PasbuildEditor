# Pasbuild Project XML Editor — Plan

## Status

Core implementation is complete. The editor handles POM, application, and library
projects with full CRUD on all known fields, dependency resolution, profile templates,
recursive submodule editing, unit tests, automatic version sync on build, and a full
build runner with live output streaming, scrolling, and plugin discovery.

## Critical Files

| File | Purpose |
|------|---------|
| `pasbuildeditor/src/main/pascal/Main.pas` | Entry point: parse argv, load file, launch UI |
| `pasbuildeditor/src/main/pascal/PasbuildEditor.ProjectModel.pas` | Class hierarchy + in-place DOM read/write |
| `pasbuildeditor/src/main/pascal/PasbuildEditor.Profiles.pas` | Built-in profile templates |
| `pasbuildeditor/src/main/pascal/PasbuildEditor.DependencyResolver.pas` | Repository browser (`~/.pasbuild/repository/`) |
| `pasbuildeditor/src/main/pascal/PasbuildEditor.UI.pas` | Full menu UI, breadcrumb, navigation |
| `pasbuildeditor/src/main/pascal/PasbuildEditor.Consts.pas` | APP_TITLE, APP_VERSION (via generated .inc) |
| `pasbuildeditor/src/main/pascal/PasbuildEditor.Version.inc` | Generated by `pasbuild genversion`; gitignored |
| `termui/src/main/pascal/TermUI.Menu.pas` | Menu, EditLine, JoinTruncated |
| `termui/src/main/pascal/TermUI.Terminal.pas` | Double-buffered terminal, TKeyCode |
| `termui/src/platform/unix/TermUI.Terminal.Platform.pas` | VT100 key parsing inc. Ctrl+arrows |
| `plugins/pasbuild-genversion` | Syncs version from project.xml → .inc on build |

## Backlog

### Infrastructure / refactor

#### 1. Update TMenu events to use TNotifyEvent

TNotifyEvent is a more common event type and is better suited to custom tools.

#### 2. Use pasbuild init to create data for test suite projects

Pasbuild may be updated with new nodes and we need to make sure we support them.
Replace hand-crafted fixture XML files with output from `pasbuild init` so fixtures
stay in sync with the pasbuild schema.

#### 3. Update default search paths

Review every place `~/.pasbuild` is hardcoded. If `GetUserDir` already resolves
correctly on all platforms this item may already be done — verify and remove the
hardcoded strings if so.

### Localisation (large, sequential)

#### 4. Add resource strings for all menu items

Use `PasbuildEditor.Strings.pas` to add resource strings for every visible string:

- Root menu: hints for Modules / Children
- Modules menu: hints for Create new module, Scan folder, Add existing path
- Profiles menu: hints for Add from template, Add blank
- Profile editing menu: hints for ID, Defines, Compiler Options, Delete, Duplicate
- Grey placeholder text: `(none)`, `(empty)`, `(inherited)`
- Every other label and hint not yet covered

This is a prerequisite for translations (#5).

#### 5. Add translations

- Use `&` in resource strings to designate the shortcut character (e.g. `&Compile`)
- Add a `TMenuItem.CreateL` helper in TermUI that extracts the `&`-marked char,
  uppercases it, and calls the existing constructor
- Add a locale-based translation loader at startup
- Add translations for: Spanish, German, Dutch, French, Portuguese, Afrikaans
